Create and edit a task

  • Right: task.create
  • Tools: list_tasks, update_tasks, import_plan
  • Pages of the app: /projects/[id]/kanban

Purpose

A task is a single step of work in a todo. On the board you see what is open, what is running and what is done.

Good to know

  • There is no task without a todo. If New task is missing or grey, create a todo first.

  • In an archived project you cannot create tasks.

  • Whether you may create or change tasks depends on your role in the project.

  • In the calm view, New task is in the command palette.

For agents

An agent creates new tasks with import_plan (an excerpt of the plan with mode: "partial", dry_run: true first). It changes status, commit and assignee directly with update_tasks. With list_tasks it finds tasks by status, assignee or text. See the chapter «Change tasks over MCP».

Example prompts

  • In the project [project], in the todo [todo], create a task «[title]» and assign it to [person]. Check the result with a dry run first.

  • Show me all my open tasks in the project [project], sorted by due date.

  • Set the task [k-123] to «In progress».

Change tasks over MCP

  • Right: task.update
  • Tools: list_projects, list_tasks, update_tasks, export_plan, import_plan, add_comment
  • Pages of the app: –

Purpose

An agent reads and changes tasks through the MCP server without loading the whole plan. Each change stays small, and the state in the planer matches the work.

Good to know

  • The agent acts as its own account, with exactly its rights. What it may not do in the project, the server refuses.

  • The planer derives the status of todo and milestone from the tasks. An agent never sets them.

  • Which statuses an agent may set depends on its role in the project. A person in the project can also decide who marks a task as done.

For agents

  • Start: list_projects gives the projects, your role and the revision of the plan.

  • Find: list_tasks with filters (assignee: "me", status, text), small with limit.

  • Status, commit, assignee: update_tasks directly, without an export and without a dry run. base_revision only when nothing may have changed in between.

  • New tasks or changed titles: export_plan filtered to one milestone, change it, import_plan with mode: "partial", with dry_run: true first.

  • Reports and questions: add_comment on the task.

  • Not over MCP: deleting tasks for good, changing rights or roles.

Example prompts

  • With list_tasks, show me my tasks in the project [project] that are «In progress» or «Review».

  • With update_tasks, set the task [k-123] to «Review» and enter the commit [hash]. Then write a short report on the task with add_comment.

  • In the milestone [milestone] of the project [project], create a task «[title]»: export only this milestone, add the task and import with mode: "partial", as a dry run first.

Create an agent and set up its access

  • Right: users.manage
  • Tools: –
  • Pages of the app: /admin/users

This task is done by people in the app. The steps are in the help of the app (Help).

Purpose

An agent is an account of its own for Claude or an assistant. It does not sign in in the browser but works through the connector (MCP) with an access, and it may do exactly what its role in the project allows.

Good to know

  • The access is a secret. It belongs in a password manager or an environment variable, never in a file under version control or in a chat.

  • If you lost the access, revoke it in the same dialog and create a new one.

  • Without a project the agent sees nothing. What it may do in the project depends on its role there.

  • The address of the MCP server and a guide for the connector are in the same dialog.

Example prompts

  • Connect to the MCP server of Mollo Planer with the variable [VARIABLE] and show me the projects you see.

  • Check with list_projects which role you have in the project [project] and what you may change there.
