Im Kontext.

Diese Anleitung zeigt Agenten, wie sie einen sicheren Zugang zum Planer erhalten und Projekte lesen oder bearbeiten. Der MCP-Server handelt immer mit den Rechten des zugehörigen Kontos. Für Agenten: /mcp/llms.txt, dasselbe als reines Markdown (englisch).

01 IDENTITÄT & ZUGRIFF

Dein Zugang beginnt beim Team.

Menschen verbinden ihr persönliches Konto über den einmalig angezeigten Zugang im Profil. Agenten verwenden stattdessen ein eigenes Agent-Konto, nicht das Konto eines Teammitglieds: Bitte die Planer-Administration, das Konto anzulegen, dich den benötigten Projekten mit der Rolle Agent zuzuweisen und einen MCP-Zugang bereitzustellen. Agent-Konten werden administrativ eingerichtet und melden sich nicht in der Weboberfläche an.

↗

Der Token ist ein Passwort. Er wird nur einmal ausgegeben. Bewahre ihn in der Secret-Verwaltung oder geschützten lokalen Konfiguration deines Agenten auf – niemals in Prompts, Repositorys, Logs oder Screenshots.

Der Server prüft jede Anfrage im Namen des Kontos. Du siehst nur freigegebene Projekte und darfst nur Aktionen ausführen, für die dieses Konto die nötigen Rechte besitzt. Persönliche Zugänge laufen nach 90 Tagen ab; Agent-Zugänge kann die Administration widerrufen oder erneuern.

02 VERBINDUNG

Agent mit dem MCP-Server verbinden.

Trage Endpunkt und Token in die MCP-Konfiguration deines Clients ein. Der .dev-Host ist TEST, .ch ist PRODUKTION; lokal verwendest du die API-Adresse deines Teams. Sende den Token als Authorization: Bearer ….

Claude Desktop

Konfiguriere den Remote-Server mit mcp-remote. Die lokale Konfiguration enthält den Token und muss geschützt bleiben; sie gehört nicht in die Versionsverwaltung. Node.js muss auf dem Rechner verfügbar sein.

{
  "mcpServers": {
    "mollo-planer": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://api.planer.mollo.dev/mcp", "--header", "Authorization:${AUTH_TOKEN}"],
      "env": { "AUTH_TOKEN": "Bearer <dein-agent-token>" }
    }
  }
}

Ersetze den Platzhalter lokal, sichere die Konfigurationsdatei und teile sie nie mit dem echten Token. Beende Claude Desktop vollständig und starte es neu, damit die Konfiguration geladen wird.

Claude Code

Trage den Server in die .mcp.json des Projekts ein. Die Datei darf eingecheckt werden, weil sie nur den Namen einer Umgebungsvariable enthält, nie das Token. Nimm eine Variable je Konto: MOLLOPLANER_<NAME>_TOKEN, zum Beispiel MOLLOPLANER_BOB_TOKEN für den Agenten Bob.

{
  "mcpServers": {
    "mollo-planer": {
      "type": "http",
      "url": "https://api.planer.mollo.dev/mcp",
      "headers": { "Authorization": "Bearer ${MOLLOPLANER_<NAME>_TOKEN}" }
    }
  }
}

Claude Code liest ${…} in url und headers beim Start, das Token bleibt also in deiner Umgebung (nicht in einer Datei unter Versionskontrolle). Setze die Variable und starte Claude Code neu; prüfen mit claude mcp list. Nenne die Variable nicht wie die Zugangsdaten eines anderen Werkzeugs (ANTHROPIC_API_KEY, NPM_TOKEN …): Claude Code liest solche Namen in headers als leer. Ist ein Authorization-Header gesetzt, fällt Claude Code für diesen Server nicht auf OAuth zurück. Alternativ auf der Kommandozeile: claude mcp add --transport http mollo-planer https://api.planer.mollo.dev/mcp --header 'Authorization: Bearer ${MOLLOPLANER_<NAME>_TOKEN}' (die einfachen Anführungszeichen stehen lassen).

Custom Connector mit OAuth (Personen)

Personen können Claude (Desktop oder claude.ai) ohne Token und ohne Node.js verbinden: Einstellungen → Connectors → einen Custom Connector mit der Adresse https://api.planer.mollo.dev/mcp hinzufügen. Claude findet die Anmeldung selbst, du bestätigst sie einmal, und Claude arbeitet danach mit deinen Rechten. Das gilt für die Konten von Personen. Ein Agent-Konto kann sich im Web nicht anmelden und nimmt das Token wie oben beschrieben.

JetBrains AI Assistant

Öffne Settings → Tools → AI Assistant → Model Context Protocol (MCP), wähle Add → As JSON und füge diese Konfiguration ein. Sie nutzt wie bei Claude Desktop mcp-remote; ersetze den Platzhalter lokal durch deinen Token. Unter Windows startet npx über cmd /c.

{
  "mcpServers": {
    "mollo-planer": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://api.planer.mollo.dev/mcp", "--header", "Authorization:${AUTH_TOKEN}"],
      "env": { "AUTH_TOKEN": "Bearer <dein-agent-token>" }
    }
  }
}

Menüpfade können je nach IDE-Version abweichen. Übernimm die Konfiguration mit Apply und starte die IDE danach neu. Der Token gehört nicht in Projektdateien, die versioniert werden.

JetBrains Junie

Trage den Server über Settings → Tools → Junie → MCP Settings ein oder bearbeite direkt die Benutzerdatei ~/.junie/mcp/mcp.json. Remote-Server werden mit url und headers beschrieben. Der Token gehört nur in die Benutzerdatei ~/.junie/mcp/mcp.json, nie in die projektweite .junie/mcp/mcp.json, die versioniert werden kann.

{
  "mcpServers": {
    "mollo-planer": {
      "url": "https://api.planer.mollo.dev/mcp",
      "headers": { "Authorization": "Bearer <dein-agent-token>" }
    }
  }
}

Menüpfade können je nach IDE-Version abweichen. Übernimm die Konfiguration mit Apply und starte Junie bzw. die IDE danach neu.

03 FÄHIGKEITEN

Nutze das passende Werkzeug.

Beim Verbinden stellt der Server seine Instruktionen und dreizehn Werkzeuge bereit. Starte mit list_projects, um Projekt-ID, Rolle und Revision zu sehen; ergänze bei Bedarf include_rights: true oder include_members: true. Lies nur die Informationen, die du für den Auftrag brauchst.

list_projectsSichtbare Projekte und Rechte
list_templatesVerfügbare Projektvorlagen
list_usersPersonen, soweit dein Recht es erlaubt
export_planPlan lesen: ganz, gefiltert oder als Übersicht
list_tasksTasks finden, flach und knapp; eine Task mit Detail
get_project_statisticsDie Zahlen eines Projekts, ohne den Plan zu lesen
import_planPlanänderungen nach Rechteprüfung eintragen
update_tasksStatus, Commit oder Zuweisung pflegen
add_comment list_commentsKommentare schreiben und lesen
create_idea list_ideasPrivate Ideen erfassen und ansehen
get_project_ai_contextFreigegebenes Projektwissen lesen

Ein Plan hat das Format planer-v2 und die Hierarchie Projekt → Milestone → ToDo → Task. IDs wie m-42, t-81 und k-105 bleiben beim Bearbeiten erhalten; neue Elemente bekommen IDs wie m-new-1. Der Server vergibt daraus die echten IDs. Listen liefern has_more und next_cursor; folge dem Cursor, bis keine weiteren Treffer vorliegen. Abgeschnittene Kommentare und Ideen lassen sich mit ihrer ID und dem nächsten Text-Offset fortsetzen.

Günstig arbeiten

Ein ganzer Export eines grossen Projekts kostet rund 20 000 Tokens, und die meisten Tasks darin sind meist erledigt. Lies in Stufen:

  1. 1

    Überblick. list_projects (IDs, Revision), dann get_project_statistics oder export_plan mit view: "outline" (rund 1 000 Tokens).

  2. 2

    Arbeit finden. list_tasks mit assignee: "me" und status: ["open", "in_progress"]. Eine Task mit allem: list_tasks mit ids und include: ["description", "comments"].

  3. 3

    Fortschritt melden. update_tasks direkt: kein Export, kein Trockenlauf vorher. base_revision ist optional.

  4. 4

    Struktur ändern. export_plan für einen Milestone, bearbeiten, import_plan mit mode: "partial". Den ganzen Export nur, um den ganzen Plan umzubauen.

Dieselben Rezepte als reines Markdown: /mcp/llms.txt.

04 SICHER SCHREIBEN

Erst prüfen. Dann eintragen.

  1. 1

    Gezielt exportieren. Bei grossen Plänen Filter wie Version, Milestone, Task-Status oder „nicht veröffentlichte“ Milestones nutzen.

  2. 2

    IDs und Revision erhalten. Verwende die exportierten IDs und bei vollständigen Planänderungen die aktuelle Revision. Bei update_tasks ist base_revision optional: ohne sie wird jede Task und jedes Feld für sich geändert; mit ihr wird der Aufruf abgelehnt, wenn sich der Plan inzwischen geändert hat, und die Antwort trägt den aktuellen Stand deiner Tasks.

  3. 3

    Trockenlauf zuerst, bei import_plan. Rufe es zuerst mit dry_run: true auf und lies alle Änderungen und Fehler, bevor du einen echten Schreibaufruf machst; ein Trockenlauf reserviert keine Revision. update_tasks ist atomar und geprüft: kein Trockenlauf nötig (dry_run: true bleibt möglich).

  4. 4

    Den passenden Modus wählen. Ein gefilterter Export ist ein Ausschnitt: schreibe ihn nur mit mode: "partial" zurück. full behandelt den Inhalt als ganzen Plan und verschiebt fehlende Elemente in den Papierkorb. In partial braucht ein bestehendes Element nur seine id und die Felder, die sich ändern; was fehlt, bleibt unverändert, revision und project dürfen fehlen, Labels und Zuweisungen gelten gegen das Projekt. base_revision bricht ab, wenn der Plan neuer ist.

!

Status nie direkt setzen: Milestone- und ToDo-Status werden aus Tasks abgeleitet. Schreibe nur Task-Status wie idea, planned, open, in_progress, review oder done.

update_tasks ändert nur angegebene Felder; commit: null und assigneeEmail: null leeren die Werte. partial ergänzt oder ändert, löscht aber nichts. Ein Titel (Milestone, ToDo, Task) hat 2 bis 160 Zeichen; ein längerer wird abgelehnt. Unbekannte Felder in einem Dokument werden ebenfalls abgelehnt, mit Pfad und Vorschlag; die Form beschreibt das JSON-Schema (auch in den Anweisungen verlinkt, die der Server mitschickt). Der Trockenlauf ersetzt keine Rechteprüfung: der Server kontrolliert jedes konkrete Feld und jede Aktion erneut. Benachrichtigungen an Zugewiesene bleiben standardmässig aus; aktiviere sie nur, wenn der Auftrag es verlangt.

05 FEHLERSUCHE

Wenn die Verbindung stockt.

401 · Unauthenticated
Token prüfen. Er könnte fehlerhaft, widerrufen oder abgelaufen sein; frage die Administration nach einem neuen Zugang.
403 · Nicht berechtigt
Das Konto hat keinen MCP-Zugang oder nicht das benötigte Projekt-Recht. Bitte das Team, Mitgliedschaft und Rechte zu prüfen.
429 · Zu viele Anfragen
Warte kurz, bevor du es erneut versuchst. Der Server begrenzt die Anfragen.
Server wird nicht angezeigt
Prüfe die MCP-Konfiguration und starte den Client vollständig neu.
