Mollo Planer.
Im Kontext.

Diese Anleitung zeigt Agenten, wie sie einen sicheren Zugang zum Planer erhalten und Projekte lesen oder bearbeiten. Der MCP-Server handelt immer mit den Rechten des zugehörigen Kontos.

TEST ENDPOINT https://api.planer.mollo.dev/mcp Testumgebung. Produktion: https://api.planer.mollo.ch/mcp. Der MCP-Server nimmt JSON-RPC-Anfragen per POST entgegen.

01 IDENTITÄT & ZUGRIFF

Dein Zugang beginnt beim Team.

Menschen verbinden ihr persönliches Konto über den einmalig angezeigten Zugang im Profil. Agenten verwenden stattdessen ein eigenes Agent-Konto, nicht das Konto eines Teammitglieds: Bitte die Planer-Administration, das Konto anzulegen, dich den benötigten Projekten mit der Rolle Agent zuzuweisen und einen MCP-Zugang bereitzustellen. Agent-Konten werden administrativ eingerichtet und melden sich nicht in der Weboberfläche an.

↗

Der Token ist ein Passwort. Er wird nur einmal ausgegeben. Bewahre ihn in der Secret-Verwaltung oder geschützten lokalen Konfiguration deines Agenten auf – niemals in Prompts, Repositorys, Logs oder Screenshots.

Der Server prüft jede Anfrage im Namen des Kontos. Du siehst nur freigegebene Projekte und darfst nur Aktionen ausführen, für die dieses Konto die nötigen Rechte besitzt. Persönliche Zugänge laufen nach 90 Tagen ab; Agent-Zugänge kann die Administration widerrufen oder erneuern.

02 VERBINDUNG

Agent mit dem MCP-Server verbinden.

Trage Endpunkt und Token in die MCP-Konfiguration deines Clients ein. Der .dev-Host ist TEST, .ch ist PRODUKTION; lokal verwendest du die API-Adresse deines Teams. Sende den Token als Authorization: Bearer ….

Claude Desktop

Konfiguriere den Remote-Server mit mcp-remote. Die lokale Konfiguration enthält den Token und muss geschützt bleiben; sie gehört nicht in die Versionsverwaltung. Node.js muss auf dem Rechner verfügbar sein.

{
  "mcpServers": {
    "mollo-planer": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://api.planer.mollo.dev/mcp", "--header", "Authorization:${AUTH_TOKEN}"],
      "env": { "AUTH_TOKEN": "Bearer <dein-agent-token>" }
    }
  }
}

Ersetze den Platzhalter lokal, sichere die Konfigurationsdatei und teile sie nie mit dem echten Token. Beende Claude Desktop vollständig und starte es neu, damit die Konfiguration geladen wird.

Claude Code

In diesem Repository ist der MCP-Server bereits in .mcp.json eingetragen und liest MOLLOPLANER_TOKEN. Stelle die Variable über die Secret-Verwaltung deiner Umgebung bereit und starte Claude Code danach neu. Prüfe bei anderen Projekten deren MCP-Konfiguration, bevor du Zugangsdaten einträgst.

03 FÄHIGKEITEN

Nutze das passende Werkzeug.

Beim Verbinden stellt der Server seine Instruktionen und elf Werkzeuge bereit. Starte mit list_projects, um Projekt-ID, Rolle und Revision zu sehen; ergänze bei Bedarf include_rights: true oder include_members: true. Lies nur die Informationen, die du für den Auftrag brauchst.

list_projectsSichtbare Projekte und Rechte
list_templatesVerfügbare Projektvorlagen
list_usersPersonen, soweit dein Recht es erlaubt
export_planPlan lesen, bei Bedarf gefiltert
import_planPlanänderungen nach Rechteprüfung eintragen
update_tasksStatus, Commit oder Zuweisung pflegen
add_comment list_commentsKommentare schreiben und lesen
create_idea list_ideasPrivate Ideen erfassen und ansehen
get_project_ai_contextFreigegebenes Projektwissen lesen

Ein Plan hat das Format planer-v2 und die Hierarchie Projekt → Milestone → ToDo → Task. IDs wie m-42, t-81 und k-105 bleiben beim Bearbeiten erhalten; neue Elemente bekommen IDs wie m-new-1. Der Server vergibt daraus die echten IDs. Listen liefern has_more und next_cursor; folge dem Cursor, bis keine weiteren Treffer vorliegen. Abgeschnittene Kommentare und Ideen lassen sich mit ihrer ID und dem nächsten Text-Offset fortsetzen.

04 SICHER SCHREIBEN

Erst prüfen. Dann eintragen.

  1. 1

    Gezielt exportieren. Bei grossen Plänen Filter wie Version, Milestone, Task-Status oder „nicht veröffentlichte“ Milestones nutzen.

  2. 2

    IDs und Revision erhalten. Verwende die exportierten IDs und bei vollständigen Planänderungen die aktuelle Revision.

  3. 3

    Trockenlauf zuerst. Rufe import_plan und update_tasks zuerst mit dry_run: true auf. Bei update_tasks ist base_revision aus dem Export Pflicht. Lies alle Änderungen und Fehler, bevor du einen echten Schreibaufruf machst; ein Trockenlauf reserviert keine Revision.

  4. 4

    Den passenden Modus wählen. Ein gefilterter Export ist ein Ausschnitt: schreibe ihn nur mit mode: "partial" zurück. full behandelt den Inhalt als ganzen Plan und verschiebt fehlende Elemente in den Papierkorb.

!

Status nie direkt setzen: Milestone- und ToDo-Status werden aus Tasks abgeleitet. Schreibe nur Task-Status wie idea, planned, open, in_progress, review oder done.

update_tasks ändert nur angegebene Felder; commit: null und assigneeEmail: null leeren die Werte. partial ergänzt oder ändert, löscht aber nichts. Der Trockenlauf ersetzt keine Rechteprüfung: der Server kontrolliert jedes konkrete Feld und jede Aktion erneut. Benachrichtigungen an Zugewiesene bleiben standardmässig aus; aktiviere sie nur, wenn der Auftrag es verlangt.

05 FEHLERSUCHE

Wenn die Verbindung stockt.

401 · Unauthenticated
Token prüfen. Er könnte fehlerhaft, widerrufen oder abgelaufen sein; frage die Administration nach einem neuen Zugang.
403 · Nicht berechtigt
Das Konto hat keinen MCP-Zugang oder nicht das benötigte Projekt-Recht. Bitte das Team, Mitgliedschaft und Rechte zu prüfen.
429 · Zu viele Anfragen
Warte kurz, bevor du es erneut versuchst. Der Server begrenzt die Anfragen.
Server wird nicht angezeigt
Prüfe die MCP-Konfiguration und starte den Client vollständig neu.
